# 资产页「批量录入模式」设计

> 日期：2026-06-21 · 状态：待实现（已过 3 路 agent review，结论并入）

## 背景与问题

录入某个月所有资产的月度快照，当前流程是：
**资产页 → 点资产 → 详情页 → 点「添加记录」→ 填 3 个字段 → 保存 → 返回 → 返回 → 下一个资产……**

资产一多，"一个个点开"的导航成本极高。本设计在**资产页**上加一个就地的批量录入模式，把 N 次「点开-填-返回」压缩成一屏内的展开/收起，最后统一提交。

不改动 `add-record` modal——它仍是从资产详情页编辑单条快照的入口；本特性是资产页上的**新增**能力。

## 目标

- 在资产页一屏内完成"一次更新一批资产本月（或任意月）净值"
- 支持补录/修改过去任意月份
- 已有快照可在原值上修改（"补录"与"修改"是同一动作）
- 单次操作可丢弃，避免误写

## 非目标

- 不替换 `add-record` modal
- 不做跨多个月份的批量录入（一次只针对一个选定月份）
- 不改快照数据模型 / repo（复用现有查询）
- **不做跨月 profit 重算链**：`profit = Δ净值 − 流入` 是跨月链式的，但本特性（与现有 `add-record` 一致）只写被编辑月份那一行，**不**回头重算后续月份已存的 profit。编辑过去月份后，其下一月的 profit 会基于旧的"上月净值"而偏旧——这是已知的、当前全局存在的行为，本期不处理。

## 交互设计

### 普通模式

- 资产页顶部新增 **「录入」按钮**（入口）。无任何资产时该按钮隐藏/禁用。
- 卡片点击行为维持现状：跳资产详情页。

### 录入模式

点「录入」进入。顶部头部**变形**为操作栏：

```
[ 取消 ]      ‹  2026 年 6 月  ›      [ 提交 (N) ]
```

- **取消**（左）：丢弃所有草稿，退出录入模式（有草稿时先 `confirmAsync` 确认）。
- **年月选择器**（中）：左右箭头切月，默认当前月；点中间标签快速跳选年月。切月前若有未提交改动 → `confirmAsync` 确认，确认后清空草稿再切。
- **提交 (N)**（右，唯一的提交入口）：N = 有改动的资产数；N=0 时置灰。
- 卡片点击行为切换为「就地展开成录入卡」。
- 提交后：若全部成功 → 退出录入模式；若有失败/跳过项 → **留在录入模式**（见错误处理）。

### 展开录入卡

点资产卡片 → 就地展开为录入卡，内容（默认三框，与 `add-record` 一致）：

- 顶部参考行：**上月净值 XXX**
- **净值 / 流入 / 收益** 三个输入框 + **「自动计算」开关**（收益 = 净值差 − 流入）
- **预填**：该月已有快照 → 预填已有值；该月无快照 → 净值预填 `getLastSnapshotBefore` 的上月净值（与 `add-record` 的起点一致），流入/收益留空
- 卡片底部两个图标按钮（**语义明确、不复用"已有"标记的图标**）：
  - **↺ 重置（左）**：把这张卡恢复到初始预填状态（有快照→恢复已有值；无快照→恢复上月净值起点），并从草稿 Map 移除（N 减 1）。不收起，便于继续改。
  - **⌃ 收起（右，向上箭头/「收起」字样）**：保留草稿并收起，计入 N。**不使用 ✓ 图标**，避免与"保存/已提交"语义混淆——真正落库只在顶部「提交」。

### 手风琴

同一时刻只展开一张卡。展开第二张时第一张自动收起，按 **收起语义**处理（保留草稿）。

### 草稿持久

草稿存活在资产页状态里，与展开/收起无关。第二次展开同一张卡 → 从草稿回填上次填的值，**信息不丢**。收起路径语义：**↺ = 恢复初始（出 Map）**、**⌃ 收起 = 留**、**展开别张 = 留（自动）**。

### 「已有」标记

普通模式与录入模式的折叠行上，用一个**与收起图标不同的视觉**标记本月有真实快照的资产：建议「已有值灰显」或一个小圆点；本会话内被改过的（在草稿 Map 中）用强调色/「已改」pill。**不使用 ✓ 图标**。该标记严格表示"本月有真实快照"，与资产行显示的（可能前向填充的）净值是两回事——避免"有数值却没标记"被误读为已填。

## 数据流

资产数量在个人理财场景下很小，采用如下策略：

- **进入录入模式 / 切月时**：调一次 `listSnapshotsByDate(selectedMonth)`（已存在，返回该月**非归档**资产的真实快照，含账户/资产名，**不**传 `forwardFill`），用于：
  1. 折叠行的「已有」标记（严格=真实快照存在）；
  2. 展开时预填已有值。
  - 注：刻意不传 `{ forwardFill }`——标记/预填只反映真实录入，不被上月带过来的值污染（与首页传 forwardFill 的用途不同）。
  - 「已有」集合应只针对**屏幕上实际渲染的资产**（与 `listAssets()` 同一份，二者都过滤 `archived = 0`，须保持一致，加注释说明）。
- **上月净值**（`getLastSnapshotBefore(assetId, selectedMonth)`）：按需查询——展开某卡片时才查那一个资产（与 `add-record.tsx:84` 一致），避免每次切月跑 N 次查询。
- **草稿状态**：`Map<assetId, Draft>`，`Draft = { netWorth, inflow, profit, autoFill }`；外加单独的 `expandedAssetId`（手风琴）。
- **"有改动"= 按值判定（非"碰过"）**：某资产入 Map 当且仅当其当前 `{netWorth, inflow, profit}` 与该月已有快照的值不同（无快照则与"空/上月净值起点"不同）。在收起/自动收起时按值比较决定入/出 Map。避免预填原值未改也产生 no-op 写入（多余的 HLC tick + 同步噪音）。
- **重开不重算**：重新展开一张卡时，以草稿里存的三个数字 + `autoFill` 为准回填，**不**用新查的上月净值重算 profit；只有用户主动编辑某框时才按 `snapshot-calc` 重算（与 `add-record` 的 `updateX` 行为一致）。
- **提交**：遍历草稿 Map，best-effort 包在 `withTransactionAsync` 内（Tauri 上为 no-op，仍逐条写）。逐个 `upsertSnapshot(assetId, selectedMonth, n, i, p)`。**可续传**：成功的从 Map 移除，失败/非法的留在 Map 并高亮，提交后留在录入模式让用户重试；全部清零才退出。

## 组件分解

`assets.tsx` 当前精简（~150 行），加入录入模式后会显著膨胀。为保持单元边界清晰：

- **`src/utils/snapshot-calc.ts`（新）**：**只抽纯数学**——`profit = netWorth − lastNetWorth − inflow` 及其两个反推（由 inflow 推 profit、由 profit 推 inflow）。供 `add-record.tsx` 与新录入卡共用。**不抽**"何时应用"的策略：`add-record` 里 `updateNetWorth` 有 `!hasExisting` 短路（编辑已有快照时改净值不重算 profit），这是它特有的策略，新卡片**不得继承**——批量编辑已有值时必须照常重算，否则会像坏了。`add-record` 顺手改为引用纯函数，但保留它自己的 apply 策略原样。
- **`src/components/MonthSelector.tsx`（新）**：年月选择器。箭头切月直接用 `src/utils/date.ts` 现成的 `prevYearMonth` / `nextYearMonth`，标签用 `formatMonthYear(ym, locale)`，零新日期数学。受控：`value` / `onChange`（沿用 `YearCalendar` 的 `{ selected, onChange }` 契约风格）。点中间标签跳选年月——可复用 `YearCalendar` 于 popover，或 `DateTimePicker`（实现时定一个）。
- **`src/components/AssetEntryCard.tsx`（新）**：展开录入卡。props：资产信息、上月净值、初始草稿、`autoFill`、`onChange(draft)`、`onReset`（↺）、`onCollapse`（⌃）。自身不碰数据库，纯受控。三个数字框 `returnKeyType` 串联，外层 `KeyboardAvoidingView` 保持当前行可见。
- **`app/(tabs)/assets.tsx`（改）**：持有录入模式状态（`entryMode` / `selectedMonth` / 草稿 Map / `expandedAssetId`）、变形头部、数据加载与提交编排。

## i18n（必交项）

新增 UI 字符串须在 `src/i18n/locales/en.json` + `zh.json` **两个**文件都加键（现有 `assets.*` 命名空间只有 noAccounts/noAssets）。至少包括：录入按钮、取消、提交（含计数）、年月标签、上月净值、「已有」/「已改」标记、切月确认标题/正文、取消确认标题/正文、提交跳过项的 `notify` 文案、净值非法提示。

## 错误处理

- 提交时三个数字框都校验（不只净值）：净值必须为数字；流入/收益非数字时不静默当 0，明确标红或提示，避免喂错自动计算。
- 提交部分失败 → 跳过项留在 Map 并高亮，`notify` 列出哪些资产未保存，**留在录入模式**便于即刻修正。
- 切月 / 取消时若有草稿 → `confirmAsync` 防误丢。**确认前先把"正在展开、尚未收起"的卡片当前输入刷进 Map**（或把"展开卡有未提交输入"纳入脏检查），否则边打字边切月会无声丢字。
- `confirmAsync` 在 web 为同步 `window.confirm`：本流程其后不接文件选择器，故不受"保持在用户手势内"的限制，`await` 正常工作。
- `listSnapshotsByDate` / `upsertSnapshot` 失败 → 沿用现有错误提示路径，不静默吞掉。

无测试框架。完成后以 `npx tsc --noEmit` + `npm run lint` 校验，并在 web + 一个原生目标手动跑通：进入录入模式、切月（带草稿确认）、展开/↺/⌃、手风琴、按值判定脏状态、提交后刷新与可续传、补录过去月份、已有值预填与修改、无快照月用上月净值预填、「已有」标记与显示值不矛盾。
